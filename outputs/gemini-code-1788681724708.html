비동기 작업 큐 (Worker Queue)

Gemini API 호출의 병목을 방지하기 위해 PostgreSQL 기반의 자체 작업 테이블과 Worker로 분리 처리합니다.

낙관적 락(Optimistic Lock) 기반 동시성 제어

다중 사용자 환경에서의 데이터 정합성 보장 및 버전 충돌(Conflict) 방지

1

증분 Polling 최적화

2~5초 주기의 가벼운 HTTP Polling

마지막 Cursor 값 이후 신규 이벤트만 Fetch

2

버전 충돌 감지(Conflict)

모든 Update 요청에 리소스 Version 검증

버전 불일치 시 HTTP 409 응답 및 덮어쓰기 방지

3

멱등성(Idempotency) 보장

작성/수정 요청 시 Idempotency Key 발급

네트워크 단절 재시도 시에도 중복 처리 방지

상태 복구 및 부하 제어 전략

네트워크 불안정으로 Cursor 유효성이 상실되면 Snapshot 단위의 Full Sync를 수행하여 정합성을 맞춥니다. 드래그 앤 드롭 등 연속 이벤트는 최종 Drop 좌표만 DB에 Commit하여 트랜잭션 부하를 최소화합니다.

오류 제어 전략 ① 데이터 무결성 보장

경합 조건(Race Condition) 발생 시 서버 방어 로직 및 트랜잭션 관리

예외 시나리오 서버 방어 로직 클라이언트(사용자) 경험
동시 편집 경합 A 사용자 Commit 이후, B 사용자가 구버전으로 Update 시도 시
409 Conflict 발생 및 최신 리소스 응답		 조용히 덮어쓰지 않고, 사용자에게 충돌 사실 알림 및 최신 데이터로 병합 유도
네트워크 재시도 중복 동일한 CUD 요청이 중복 유입 시

서드파티 API 및 부모 DB 연결 장애 시 시스템 코어 로직 보호 (Fail-safe)

유효 기여(Valid Contribution) 기준

메모의 최종 상태가 `Accepted`이며, 문서의 답변 텍스트로 참조(Referenced)된 Lineage 트리 내의 모든 참여자

기여 인정 제외 대상 (Noise Filtering)

내용 변경 없는 좌표 이동(Positioning), 카테고리(Section) 변경, 단순 담당자 태그 변경 등 메타데이터 변동

최종 점수 캘큘레이션

메모와 코멘트의 사용자별 원점수를 각 영역 합계 100으로 비례 정규화한 뒤, 고정 가중치 50:50으로 최종 점수를 계산합니다.

결과 및 산출 근거 덤프는 관리자 API로만 노출되며, 재평가 시 기존 로그를 파기하지 않고 버저닝(Versioning)하여 무결성을 유지합니다.

HTTP Error Code Signature Frontend UI 핸들링 전략
