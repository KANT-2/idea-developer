# 기능 명세

## 1. 문서 목적

현재 사용자 화면과 서버가 제공하는 기능을 정상 흐름, 권한, 데이터 변화와 예외 처리 관점에서
정리한다. 정책의 최우선 기준은 `requirements/CURRENT_REQUIREMENTS.md`이며, 세부 HTTP 오류는
`EXCEPTION_CATALOG.md`를 따른다.

## 2. 사용자와 외부 연동

### 2.1 인증

- 독립 실행 모드는 이메일 6자리 OTP로 Django session을 만든다.
- OTP는 해시로 저장하고 10분 후 만료되며 한 번만 사용할 수 있다.
- 실패 5회, 재전송 60초, 이메일·IP별 요청 제한을 적용한다.
- 계정 존재 여부와 무관하게 OTP 요청 화면에는 같은 응답을 표시한다.
- `DEBUG=true`에서만 부모 VIEW의 활성·승인 사용자를 검색하는 개발 로그인을 제공한다.
- 운영 통합 시 부모 인증으로 교체하더라도 로컬 사용자는 외부 `user_id`의 session 매핑일 뿐
  회원 원장이 아니다.

### 2.2 IntegrationContext

인증된 요청은 `user_id`, `round_id`, `participant_id`, `team_id`, 부모 역할과 관리자 여부를 가진
Context로 변환한다. 회차 팀 작업은 URL이나 프론트 입력을 신뢰하지 않고 부모 VIEW에서
`user_id + round_id` 조합을 다시 확인한다.

- 회차 없는 PRD: 명시적 참여자 관계로 접근한다.
- 과거 회차 PRD: 현재 회차와 달라도 명시적 참여자는 접근할 수 있다.
- 회차 팀 PRD: 해당 회차 참가자와 팀 관계가 확인되어야 한다.
- VIEW 장애: 검증이 필요한 쓰기 작업은 fail closed로 거절한다.

`post_completion_review` 코멘트를 작성할 수 있으며 해당 코멘트는 기여도에서 제외한다.

## 4. 홈 대시보드

### 정상 흐름

- 접근 가능한 PRD만 KPI와 목록에 포함한다.
- KPI는 전체, 진행 중, 완료, 평균 완성도, 보류, 이번 주 마감을 제공한다.
- 탭·상태·유형·마감일 범위·학생·팀·회차 필터와 정렬, 페이지네이션은 서버에서 처리한다.
- `mine`과 `viewer` 범위를 구분한다.
- tutor 화면은 `튜터 관리`와 `내 PRD`를 분리한다. 튜터 관리에서는 본인이 tutor로 참여한
  PRD를 학생별로 검색할 수 있다.
- PRD 카드의 D-Day와 72시간 NEW 표시는 저장값이 아니라 날짜로 계산한다.
- 최근 활동은 참여자 추가와 코멘트 생성 등을 보여주고 더보기는 페이지네이션한다.

### 계산 원칙

- 완성도는 삭제·보류되지 않은 질문 중 완료된 질문의 비율이다. 질문이 없으면 0이다.
- 평균 완성도는 카드와 동일한 `completion_rate`의 평균이다.
- AI 코칭 횟수는 품질이나 진행 상태로 오해되지 않도록 홈 KPI·카드·정렬 조건에 노출하지 않는다.
- 이번 주 마감은 사용자 날짜 기준 오늘부터 6일 뒤까지이며 `completed`, `dropped`는 제외한다.

### 주요 예외

- 결과 없음은 오류가 아니라 빈 목록과 0 KPI로 응답한다.
- 잘못된 필터·페이지 값은 `400 validation_error`로 거절한다.
- 사용자 정보가 일부 없으면 외부 ID를 노출하기보다 안전한 표시 이름을 사용한다.

## 5. PRD 생성과 참여자

### 생성 흐름

1. `new_product`, `new_feature`, `improvement` 중 유형을 선택한다.
2. 제목, 한 줄 소개, 마감일과 참여자를 입력한다.
3. 서버가 사용자·회차·팀·참여자 유효성을 다시 확인한다.
4. 생성자를 owner로 고정하고 유형 템플릿의 섹션과 질문을 복제한다.
5. `Idempotency-Key`로 네트워크 재시도의 중복 생성을 막는다.

회차 없는 개인 PRD와 일반 팀 PRD도 만들 수 있다. 회차 팀 PRD만 부모 VIEW의 팀 관계를
필수로 검증한다. 참여자는 초대 수락 없이 즉시 추가되며 동일 사용자는 한 번만 저장한다.

### 생성 이후 참여자 관리

- owner가 사용자 검색 또는 현재 팀 불러오기로 참여자를 추가한다.
- owner 자신은 제거하거나 다른 역할로 변경할 수 없다.
- editor, tutor, viewer 사이의 역할 변경과 참여자 제거를 지원한다.
- 참여자 수정에도 resource `version`을 사용한다.
- 참여자 추가가 commit되면 추가된 사용자에게 Slack DM을 보낸다.
- Slack 실패는 최대 3회 재시도하지만 PRD 저장을 롤백하지 않는다.

## 6. PRD 작성과 상태

### 작성

- 제목·한 줄 소개·마감일·상태와 질문별 답변을 저장할 수 있다.
- 질문별 저장과 전체 저장을 모두 지원한다.
- 질문을 보류하면 완성도와 AI 충족도 입력에서 제외한다.
- PRD 전체 Markdown 내보내기를 제공한다.
- 메타데이터, 질문, 참여자와 코멘트는 각자의 최신 `version`을 기준으로 수정한다.
- PRD 상세 초기 조회는 브라우저 캐시를 사용하지 않고 최신 서버 상태를 불러온다.

### 상태

- 상태는 `in_progress`, `completed`, `held`, `dropped`만 사용한다.
- 마감일이 지난 `in_progress` 또는 `held` PRD는 자정 유지보수에서 자동 완료한다.
- 요청 시 접근 경로에서도 기한 초과 여부를 보정하여 스케줄 누락에 대비한다.
- owner가 미완료 질문을 가진 PRD를 수동 완료하려면 명시적으로 확인해야 한다.
- owner 또는 관리자는 완료 PRD를 이유와 함께 재개할 수 있다.
- 자동 완료된 PRD는 마감일을 오늘 이후로 바꾼 뒤 재개한다.

### 완료 잠금

완료 후 답변, 일반 코멘트, 메모, 담당자, 위치, 상태, 연결선과 AI 반영을 잠근다. tutor의 완료 후
리뷰 코멘트만 예외이며 PRD 수정이 필요하면 owner 또는 관리자가 먼저 재개한다.

## 7. 코멘트와 알림

- PRD 전체 또는 특정 질문을 선택하여 코멘트를 남긴다.
- owner/editor 일반 코멘트는 기여도 평가 대상이다.
- tutor의 guidance, review, post-completion review는 기여도에서 제외한다.
- 작성 당시 역할을 snapshot으로 보존한다.
- 작성자만 자신의 활성 코멘트를 수정·소프트 삭제할 수 있다.
- 코멘트 저장이 commit된 후 작성자를 제외한 대상 참여자에게 Slack DM을 보낸다.
- 알림 전송 실패는 코멘트 저장 성공 여부에 영향을 주지 않는다.

## 8. 브레인스토밍

### 보드 버전

- PRD는 여러 캔버스 버전을 가질 수 있다.
- 최초 진입 시 `display_order`가 가장 앞선 최신 캔버스를 표시하고 버전 목록도 같은 순서로 보여준다.
- 새 버전은 선택한 보드의 활성 노드와 연결을 복제하고 lineage를 유지한다.
- 편집 권한자는 보드 순서를 바꿔 가장 위 보드를 최신으로 지정할 수 있다.
- 최신 보드만 메모·연결선·자동 정렬·PRD 반영을 수정할 수 있고 과거 버전은 조회 전용이다.
- 최신 보드를 삭제하면 다음 보드를 즉시 최신으로 승격한다. 마지막 활성 보드는 삭제할 수 없다.

### 메모와 상태

- 일반 메모 생성 시 작성자와 최초 담당자는 로그인 사용자다.
- 작성자는 바꿀 수 없고 담당자는 PRD 참여자로 변경할 수 있다.
- 미분류 영역은 `default`, 섹션 안은 `accepted`, 보류 영역은 `held`로 해석한다.
- 위치·섹션 이동은 드래그 종료 시 한 번만 저장한다.
- 보류는 메모를 남기되 섹션을 해제하고 연결선을 한 트랜잭션에서 영구 삭제한다.
- 보류 해제 시 유효한 직전 섹션을 기억해 돌아가며, 해당 섹션이 사라졌으면 미분류 안전 좌표로
  이동한다. 삭제된 연결선은 자동 복원하지 않는다.
- 사용자 삭제는 30일 소프트 삭제다. 복원은 관리자 정책 범위에서 처리하고 미분류 기본 위치로
  돌아가며 살아 있는 상대 노드의 연결만 복원 대상이 된다.

### 연결과 동기화

- 자기 연결, 중복 연결, 다른 캔버스·삭제 노드 연결을 거절한다.
- 생성에는 idempotency key, 변경에는 node/connection version을 사용한다.
- 브라우저는 2~5초 polling으로 cursor 이후 변경만 받는다.
- cursor가 만료되거나 네트워크가 재연결되면 보드 전체를 다시 조회한다.
- 자동 정렬은 활성 note만 대상으로 모든 version이 맞을 때 한 트랜잭션으로 저장한다.

### 분류 결과

사용자 화면의 분류 결과는 AI가 아니라 서버가 현재 노드의 섹션과 상태를 계산한 통계다.
Legacy AI 분석·분류 API는 신규 화면에서 호출하지 않는다. 브레인스토밍 Markdown 내보내기는
제거되었다.

## 9. AI 코치·진단·PRD 반영

### 공통 비동기 처리

- 웹 요청은 PostgreSQL 작업 테이블에 job을 넣고 worker가 Gemini를 호출한다.
- job은 대기, 실행, 성공, 실패, 취소 상태와 timeout, lease, 제한된 재시도를 가진다.
- 모델 키와 모델명은 환경변수로 관리한다.
- system instruction과 사용자 데이터를 분리하고 JSON schema와 반환 ID를 서버 데이터로
  재검증한다.

### AI 코치

- `(PRD, section 또는 전체, user)`별 대화를 복원한다.
- 화면에는 저장된 대화를 제공하지만 모델에는 최근 3턴과 크기가 제한된 PRD context만 전달한다.
- 사용자 메시지는 plain text로 저장하고 출력 시 escape한다.
- AI가 답변 변경안을 제안해도 사용자가 승인하기 전에는 PRD를 바꾸지 않는다.
- 대화는 append 방식으로 저장하여 동시 요청이 이전 기록을 덮어쓰지 않게 한다.
- 마지막 활동으로부터 30일 뒤 만료 대상으로 정리한다.

### AI 진단과 초안

- AI 진단 한 번으로 PM, 엔지니어링, 투자자 관점을 함께 생성한다.
- 질문 초안은 대상 질문과 현재 version을 기준으로 만들고 즉시 저장하지 않는다.
- 사용자가 검토·수정 후 적용할 때 질문 version을 다시 확인한다.
- 보류 질문은 진단과 완성도 입력에서 제외한다.

#### 관점별 PRD 전체 초안

- 사용자는 PM, 엔지니어링, 투자자 중 한 관점을 선택하고 PRD 전체 활성 질문의 답변 초안을 요청한다.
- 요청은 `PRD_PERSPECTIVE_DRAFT/perspective_draft` AI job으로 등록되며 웹 요청과 분리된 worker가 처리한다.
- 최근 동일 사용자의 같은 관점 AI 진단이 현재 질문 version과 일치하면 참고 정보로 사용한다. 진단이
  없거나 오래됐거나 실패했어도 현재 PRD context만으로 초안 생성은 계속할 수 있다.
- 결과는 모든 현재 질문을 정확히 한 번씩 포함해야 한다. 서버는 중복·누락 질문 ID, 다른 PRD의
  질문 ID와 빈 초안을 거절하고 Markdown을 정화한다.
- 생성 결과는 즉시 답변에 저장하지 않고 질문별 미리보기와 생성 이유를 모달에 표시한다. 사용자는
  전체 또는 일부 질문만 선택해 반영할 수 있다.
- 반영 시 job 소유자, PRD 접근 권한, AI 적용 권한, job 성공 상태와 질문 version을 다시 확인한다.
  미리보기 이후 질문이 변경되면 `409 Conflict`로 반영하지 않는다.
- 미리보기의 질문별 `AI 채팅으로 가기`는 해당 섹션의 AI 코치 패널을 열고 질문·초안을 입력란에
  미리 채운다. 사용자가 전송하기 전에는 채팅 메시지나 PRD 답변을 저장하지 않는다.
- 전체 PRD를 한 번에 생성하는 작업 특성을 고려해 요청 timeout은 100초로 설정한다. 작업 상태,
  취소, 제한된 재시도와 사용량 기록은 공통 AI job 정책을 따른다.
- 권한, 입력, 작업 상태, version과 외부 연동의 예상 오류는 HTML 오류 화면 대신 공통 JSON으로
  반환한다. 작성 화면은 현재 입력과 미리보기를 유지한 채 고정 알림으로 원인과 재시도 방법을
  표시한다.

### 브레인스토밍 PRD 반영

- 기본 대상은 섹션에 배치된 accepted 메모이며 사용자가 선택한 default 메모를 추가할 수 있다.
- held, 삭제 메모와 섹션 미지정 accepted 메모는 자동 반영하지 않는다.
- AI는 기존 답변과 메모를 단순 연결하지 않고 하나의 자연스러운 답변으로 통합한다.
- 미리보기 단계에서는 DB 답변을 변경하지 않는다.
- 승인 시 `preview_request_id`, idempotency key, 노드·질문 version을 모두 재검증한다.
- 승인된 질문만 저장하고 근거 메모, 이전·통합 답변, 모델과 프롬프트 버전을 기록한다.

## 10. 기여도

- PRD 완료 후 별도 AI job으로 계산하며 실패해도 완료 상태는 유지한다.
- 메모 기여도는 실제 PRD 반영에 사용된 accepted 메모를 lineage별로 한 번만 센다.
- 최초 작성자와 의미 있는 내용 편집자에게 반영 confidence에 따라 기여를 인정한다.
- 단순 섹션 이동이나 담당자 변경만으로 새로운 내용 기여를 만들지 않는다.
- 코멘트 기여도는 owner/editor의 적격 일반 코멘트가 최종 답변에 의미적으로 반영된 정도다.
- tutor 코멘트와 `is_contribution_eligible=false`는 제외한다.
- 각 축을 사용자별 100으로 정규화한 뒤 `메모 50% + 코멘트 50%`로 계산한다.
- 재개 후 다시 완료하면 이전 결과를 덮어쓰지 않고 새 계산 버전을 만든다.
- 결과 조회와 동일 입력 재평가는 staff/superuser만 가능하다.

## 11. 삭제와 보존

- PRD 삭제는 즉시 화면과 일반 조회에서 숨기는 소프트 삭제다.
- 휴지통에서 복구할 수 있다. 휴지통의 삭제 확인은 사용자에게 `삭제 완료`로 표시하지만
  DB에서는 복구를 막는 purge 요청만 기록한다.
- 삭제 후 30일이 된 PRD와 메모는 매일 자정 유지보수에서 영구 삭제한다.
- 삭제 대상이 없어도 유지보수 명령은 성공하며 반복 실행해도 같은 결과를 유지한다.
- PRD의 상세 변경·AI·기여도 데이터는 함께 삭제하고 독립 삭제 사실 감사 로그는 장기 보존한다.

## 12. 현재 제공하지 않거나 미결정인 기능

제공하지 않는 사용자 기능은 AI 브레인스토밍 분석, AI 항목 분류, AI 사용 기록 화면, PRD 수정
이력 화면, 브레인스토밍 Markdown 내보내기와 즉시 영구 삭제다.

부모팀과 결정할 항목은 기여도 전달 payload·인증·멱등성, `results_scoreinput` 도입 여부와 부모
이관 이후 추가 공통 감사 로그의 책임·보존기간이다. 결정 전에는 임의로 구현하지 않는다.
