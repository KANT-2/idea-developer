# 07. AI로 코딩할 때의 팀 규칙

AI가 만든 코드도 우리 팀 코드입니다. 이해·검토·테스트 책임은 팀원에게 있습니다.

## 한 번에 요청할 범위

- 단계별 프롬프트 하나만 보냅니다.
- 현재 branch와 구현 범위를 명시합니다.
- 수정 가능한 파일 범위를 알려줍니다.
- 기존 시나리오 문서를 먼저 읽게 합니다.
- 구현 후 파일 목록과 테스트 결과를 보고하게 합니다.

## AI에게 항상 붙일 문장

```text
현재 branch의 작업 범위 밖 파일을 임의로 수정하지 마.
기존 사용자 변경을 덮어쓰지 마.
비밀값과 실제 사용자 데이터를 코드·테스트·로그에 넣지 마.
변경 전 관련 파일과 기준 문서를 읽고, 구현 후 테스트를 실행해줘.
수정 파일, 이유, 테스트 결과, 남은 작업을 보고해줘.
```

## 생성 결과를 팀원에게 나누는 방법

AI에게 모든 기능을 한 번에 commit하게 하지 않습니다.

1. 먼저 파일 목록과 의존 관계만 제안받습니다.
2. 팀장이 작업 묶음을 정합니다.
3. 팀장이 결과를 정확한 파일 경로와 파일 전체 코드로 나눕니다.
4. 팀원은 전달받은 코드를 미리 만들어진 폴더에 새 파일로 추가합니다.
5. 팀원별 branch에서 commit·push하고 `develop` 대상 PR을 만듭니다.
6. 팀장이 의존 순서대로 merge하고 단계 전체를 테스트합니다.

## 검토 체크리스트

- 시나리오와 일치하는가
- 이해하지 못한 코드가 있는가
- 권한 검사가 서버에 있는가
- VIEW에 쓰기를 시도하지 않는가
- 실제 개인정보가 fixture에 들어가지 않았는가
- 테스트가 실제로 실행됐는가
- 불필요한 Redis, Celery, Channels가 추가되지 않았는가
- 브레인스토밍 외 화면에 React가 퍼지지 않았는가
