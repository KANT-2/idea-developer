# 예외 처리 목록

## 1. 공통 응답 원칙

모든 API는 다음 envelope를 사용한다.

```json
{
  "ok": false,
  "data": null,
  "error": {
    "code": "version_conflict",
    "message": "사용자에게 표시할 메시지",
    "details": {}
  },
  "meta": {
    "request_id": "요청 추적 ID"
  }
}
```

예상 가능한 사용자 오류는 stack trace를 응답에 노출하지 않는다. 처리하지 못한 API 예외는 서버에
request ID와 함께 기록하고 `500 internal_error`로 변환한다.

일반 화면의 잘못된 주소는 개발 모드에서도 Django 기술 404를 노출하지 않고, 홈·이전 화면으로
돌아갈 수 있는 제품 404 화면을 표시한다. 화면의 `fetch` 요청이 로그인 HTML, 프록시 오류 HTML,
빈 응답 또는 네트워크 실패를 받으면 JSON 파싱 오류로 전파하지 않고 현재 입력과 화면을 유지한 채
재로그인·재시도 안내를 표시한다.

## 2. HTTP 상태 기준

| 상태 | 대표 code | 의미와 화면 처리 |
|---:|---|---|
| 400 | `validation_error`, `invalid_json`, `invalid_parameter` | 입력값을 유지하고 해당 필드 가까이에 안내한다. |
| 401 | `authentication_required` | 로그인 화면으로 이동하되 안전한 내부 `next`만 전달한다. |
| 403 | `permission_denied`, `csrf_failed` | 권한 재조회 후 작업을 막는다. CSRF이면 새로고침을 안내한다. |
| 404 | `not_found` | 존재 여부를 과도하게 노출하지 않고 목록으로 돌아갈 경로를 제공한다. |
| 405 | `method_not_allowed` | 프론트 호출 방식 오류로 기록하고 자동 재시도하지 않는다. |
| 409 | `version_conflict`, `status_conflict`, `duplicate_connection` | 최신 데이터를 반영하고 다시 확인하게 한다. 자동 덮어쓰기하지 않는다. |
| 429 | `ai_usage_limit_exceeded` 또는 요청 제한 code | 대기 시간을 알리고 중복 요청을 막는다. |
| 500 | `internal_error` | 입력을 보존하고 request ID를 표시하여 운영 로그와 연결한다. |
| 503 | 외부 연동 장애 계열 | 쓰기를 중단하고 외부 연동 복구 후 재시도한다. |

## 3. 인증과 외부 VIEW

| 상황 | 서버 처리 | 사용자 처리 |
|---|---|---|
| 미등록·비활성·미승인 이메일로 OTP 요청 | 계정 존재 여부를 노출하지 않는 동일 응답 | 같은 안내 문구 표시 |
| OTP 만료·재사용·5회 실패 | 검증 거절, 사용 또는 잠금 상태 유지 | 새 코드 요청 또는 제한 시간 안내 |
| 60초 이내 재전송·요청 과다 | `429` | 카운트다운 동안 버튼 비활성화 |
| 외부 `user_id` 매핑 없음 | session 생성 또는 제품 접근 거절 | 다시 로그인 또는 관리자 문의 안내 |
| 회차 선택값 위조 | VIEW 재검증 후 `403` | 권한 없음 표시 |
| 현재 회차 없음 | 회차 없는 기능만 허용하고 임의 최신 회차를 선택하지 않음 | 일반 PRD 생성 또는 회차 없음 안내 |
| 해당 회차 참가정보 없음 | 회차 팀 쓰기 `403` | 다른 회차 선택 안내 |
| 부모 VIEW 장애 | 검증이 필요한 쓰기 fail closed | 일시적 연동 장애 안내, 저장 성공으로 표시 금지 |

## 4. 홈과 PRD 생성

| 상황 | 서버 처리 | 사용자 처리 |
|---|---|---|
| 접근 가능한 PRD 없음 | 성공 응답, KPI 0과 빈 목록 | 빈 상태와 새 PRD 동작 표시 |
| 필터 결과 없음 | 성공 응답, 빈 페이지 | 필터 초기화 버튼 표시 |
| 잘못된 날짜 범위·정렬·페이지 | `400 validation_error` | 잘못된 조건만 수정 |
| 동일 생성 요청 재전송 | 같은 idempotency key이면 최초 결과 재사용 | 카드 한 개만 표시 |
| 같은 key에 다른 payload | 충돌 또는 검증 오류 | 새 key로 명시적 재요청 |
| 중복 참여자 선택 | DB unique와 서비스에서 한 명으로 합침 | 선택 상태 한 번만 표시 |
| 비활성·존재하지 않는 참여자 | 생성·추가 거절 | 유효하지 않은 참여자 표시 |
| 동명이인 | user ID로 구분하고 필요 시 일부 이메일·팀 표시 | 이름만 보고 자동 선택 금지 |
| Slack 초대 알림 실패 | 최대 3회 일시 재시도, DB commit 유지 | PRD 생성·참여자 추가 성공은 유지 |

## 5. PRD 편집·상태·코멘트

| 상황 | 서버 처리 | 사용자 처리 |
|---|---|---|
| 다른 사용자가 먼저 PRD·질문·참여자·코멘트 수정 | `409 version_conflict`와 최신 resource 반환 | 최신값을 보여주고 재편집 선택 제공 |
| viewer 또는 tutor가 PRD 내용 수정 | `403` | 편집 control 숨김과 서버 오류 안내 |
| owner 제거·역할 변경 | `400 validation_error` | owner 고정 이유 표시 |
| 완료 PRD 일반 수정 | `403` 또는 상태 충돌 | 읽기 전용 표시 |
| 미완료 질문이 있는 수동 완료 | `confirm_incomplete` 없으면 `400` | 재확인 modal 제공 |
| 완료가 아닌 PRD 완료/재개 요청 | `409 status_conflict` | 현재 상태로 화면 갱신 |
| 자동 완료 PRD의 지난 마감일로 재개 | `400`, 미래 마감일 요구 | 마감일 변경 control로 안내 |
| tutor가 진행 중 PRD에 완료후 리뷰 작성 | `403` | 일반 지도·리뷰 유형 사용 안내 |
| 일반 사용자가 완료 PRD에 코멘트 | `403` | 잠금 표시 |
| 다른 작성자의 코멘트 수정·삭제 | `403` | 작성자에게만 메뉴 표시 |
| 질문과 다른 PRD의 comment target | `400` | 질문 목록 재조회 |

## 6. 브레인스토밍

| 상황 | 서버 처리 | 사용자 처리 |
|---|---|---|
| 캔버스 없음 | 조회/최초 생성 계약에 따라 생성하거나 검증 오류 | 초기화 동작 제공 |
| 다른 PRD의 canvas ID | `400 validation_error` | 최신 보드 목록 다시 조회 |
| 이전 버전에서 메모·연결선·자동 정렬·PRD 반영 시도 | `403 permission_denied` | 조회 전용 안내와 최신 보드 이동 제공 |
| 보드 순서에 중복·누락·다른 PRD ID 포함 | `400 validation_error` | 활성 보드 목록을 다시 불러온 뒤 재정렬 |
| 이전 보드 또는 마지막 활성 보드 삭제 시도 | `400 validation_error` | 최신 보드만 삭제 가능하거나 마지막 보드 보존 이유 안내 |
| 보고 있던 최신 보드가 다른 사용자에게 삭제됨 | 최신 보드 ID와 change event 반환 | 현재 최신 보드로 자동 전환하고 전체 재동기화 |
| 노드·연결 version 불일치 | 전체 변경 취소, `409`와 최신 데이터 | 최신 메모를 표시하고 재시도 여부 확인 |
| 보류 중 연결선 집합이 변경됨 | transaction 취소, `409 connection_version_conflict` | 보드 재조회 후 다시 보류 |
| 자기 연결 | `400 validation_error` | 두 번째 선택을 취소하고 안내 |
| 같은 노드 쌍 중복 연결 | `409 duplicate_connection`과 기존 연결 반환 | 기존 연결을 즉시 표시 |
| 다른 캔버스·삭제 노드 연결 | `400` | 선택 상태 초기화 |
| 드래그 중 상대가 노드를 삭제 | 최종 PATCH 거절 | 보드 재동기화 |
| 자동 정렬 중 하나라도 충돌 | batch 전체 rollback | 최신 보드 재조회 후 재실행 |
| held 메모 보류 해제 | 유효한 직전 섹션으로 복귀, 섹션이 없으면 미분류 안전 좌표, 연결 자동 복원 없음 | 돌아간 섹션을 표시하고 필요하면 연결을 다시 생성 |
| polling cursor 무효·오래됨 | full refresh 신호 | 노드·연결·통계를 전체 재조회 |
| 인터넷 끊김 | DB 상태 변경 없음 | 오프라인 표시 후 재연결 시 전체 동기화 |

## 7. AI 작업

| 상황 | 서버 처리 | 사용자 처리 |
|---|---|---|
| 활성 프롬프트 없음 | `409 ai_prompt_not_configured` | 준비 중 안내, 무한 재시도 금지 |
| 사용 한도 초과 | `429 ai_usage_limit_exceeded` | 재시도 가능 시점 안내 |
| provider timeout | job 실패 또는 정책 범위 재시도, 실패 로그 기록 | 입력 유지와 재시도 버튼 제공 |
| 사용자 취소 | cancellable 상태만 cancelled 전환 | 결과 적용 control 비활성화 |
| 성공·취소 job 재취소/재시도 | `409 invalid_job_state` | 최신 job 상태 반영 |
| Gemini JSON schema 불일치 | 결과 폐기, failed 로그 | 잘못된 내용을 화면이나 DB에 적용하지 않음 |
| AI가 다른 node/section/question ID 반환 | 서버 대조 실패 후 결과 폐기 | 재시도 안내 |
| 질문 초안 후 질문이 변경됨 | `409 version_conflict` | 최신 답변과 초안을 비교 |
| 관점별 초안에 지원하지 않는 persona | `400` 입력 오류 | PM·엔지니어링·투자자 중 다시 선택 |
| 관점별 초안을 만들 활성 질문 없음·모든 질문 보류 | `400` 입력 오류, AI 미호출 | 질문 보류를 해제하거나 PRD 구조를 먼저 확인 |
| 관점별 초안이 질문을 누락·중복하거나 다른 ID 참조 | 결과 검증 실패 후 폐기 | DB에 반영하지 않고 재시도 안내 |
| 관점별 초안 미리보기 후 질문 변경 | `409 version_conflict`, 해당 질문 미반영 | 최신 질문과 로컬 초안을 비교한 뒤 새로 요청 |
| 관점별 초안 여러 건 반영 중 한 질문이 보류·충돌 | transaction 전체 rollback | 어느 질문도 저장하지 않고 최신 상태로 다시 선택 |
| 같은 질문 중복 승인·같은 반영 재전송 | 중복 승인은 `400`, 이미 반영된 version 재전송은 `409`; 답변 행 중복 없음 | 최신 답변을 다시 조회 |
| viewer·tutor 또는 completed PRD에서 관점별 초안 요청 | `403` | 편집 가능한 owner/editor가 진행 중 PRD에서 요청 |
| 관점별 초안 예상 오류 | 공통 JSON envelope에 구체적인 첫 필드 메시지와 request ID 반환 | 현재 작성 화면의 고정 알림·모달을 유지하고 기본 오류 페이지로 이동하지 않음 |
| PRD 반영 미리보기 후 노드·질문 변경 | 반영 취소, `409` | 새 미리보기 생성 |
| 같은 승인 요청 재전송 | idempotency 결과 재사용 | 답변 중복 저장 없음 |
| AI 기여도 평가 실패 | `contribution_status=failed`, PRD completed 유지 | 관리자에게 재평가 가능 상태 표시 |

## 8. 삭제·정리·운영

| 상황 | 서버 처리 | 사용자 처리 |
|---|---|---|
| PRD 삭제 | 소프트 삭제 후 일반 조회에서 제외 | 홈으로 이동하고 삭제 완료 표시 |
| 휴지통에서 복구 | purge 미요청이고 보존기간 내이면 복구 | 원래 목록에 다시 표시 |
| 휴지통 삭제 확인 | purge 요청 기록, 즉시 물리 삭제하지 않음 | 삭제 완료 표시, 복구 메뉴 제거 |
| 보존기간 전 영구 삭제 시도 | 정리 대상에서 제외 | 사용자 직접 영구 삭제 기능 없음 |
| 30일 경과 | 자정 유지보수에서 관련 데이터를 transaction으로 제거 | 더 이상 조회 불가 |
| 삭제 대상 0건 | 성공, 삭제 수 0 | 오류 알림 없음 |
| 유지보수 중복 실행 | 이미 처리한 행은 건너뛰는 멱등 처리 | 별도 조치 없음 |
| 자정 scheduler 누락 | PRD 접근 시 마감 보정, 다음 실행에서 정리 | 운영 경고와 scheduler 복구 |
| Slack 최종 실패 | 도메인 저장 유지, 서버 경고 로그 | 핵심 작업 실패로 표시하지 않음 |
| HTML·빈 API 응답 | JSON으로 오인하지 않고 응답 형식 오류로 처리 | 현재 화면과 입력을 유지하고 재로그인·재시도 안내 |
| 오래된 HTML과 최신 정적 파일의 일시적 불일치 | 선택 기능의 누락 요소가 전체 초기화를 중단하지 않도록 방어 | 새로고침 안내, PRD 본문은 계속 조회 가능 |

## 9. 예외 구현 체크리스트

- 쓰기 전에 인증, IntegrationContext, PRD 접근 권한과 완료 잠금을 모두 검사했는가?
- 프론트에서 control을 숨겨도 서버 검사를 생략하지 않았는가?
- 동시 수정 resource에 version 또는 idempotency key가 있는가?
- 다중 행 변경은 하나라도 실패하면 transaction 전체가 rollback되는가?
- 외부 VIEW, Gemini, Slack 장애가 데이터 무결성을 깨뜨리지 않는가?
- 사용자 메시지에 stack trace, 비밀값과 불필요한 외부 ID가 노출되지 않는가?
- 빈 결과와 반복 요청이 정상적인 멱등 성공으로 처리되어야 하는지 확인했는가?
- 새 예외를 추가했다면 `REQUIREMENTS_TRACEABILITY.md`에 회귀 테스트를 연결했는가?
